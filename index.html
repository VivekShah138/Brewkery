Skill & AI Evaluation Architecture

Important Architecture Guideline: Do NOT Use SQLite / Room!

No local database (SQLite/Room/DataStore) is required. All cart items and order state can simply live in memory inside a shared ViewModel or singleton Repository (using Kotlin StateFlow). When the app closes, it is completely expected and fine for the cart to reset. Let your AI workflow help you scaffold a clean in-memory state.

Core Requirements (Must-Have)

70% SCORE
  • API Fetch: Fetch data from GitHub raw endpoint using Retrofit/Ktor with Coroutines.
  • Screen 1 (Menu): Render categories and items (image via Coil/Glide, title, price, rating).
  • Screen 2 (Detail): Tap an item to view full photo, description, ingredients, and "Add to Cart".
  • Screen 3 (Cart): View added items, calculate subtotal + flat delivery + tax.
  • Screen 4 (Order Done): Clear in-memory cart, display randomized ticket ID (e.g. #BK-83921) and "PREPARING" state.
  • AI Workflow: Provide AI_WORKFLOW.md showing 2–3 prompts used and 1 AI bug you caught.

Bonus Features (Nice-to-Have)

30% SCORE
  • Dynamic Customization: Size picker (Tall/Grande/Venti) recalculating subtotal on Screen 2.
  • Search & Filter: Live search bar or category chips filtering on Screen 1.
  • Promo Code: Simple coupon logic (e.g., ROAST10 gives 10% off on cart).
  • Unit Tests: 1 simple unit test verifying subtotal/tax calculation logic.
  • Jetpack Compose: 100% declarative Compose implementation over legacy XML.
